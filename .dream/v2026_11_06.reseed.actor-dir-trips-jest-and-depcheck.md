# 🌙 dream: an actor dir inside the worktree trips jest and depcheck

kind: reseed · owner: the jest + depcheck config template (declapract) and the rhachet actor layout · caught 2026-11-06

## .the cue that fired

the 5.3 verification run of the `unauthed` subpath route: `rhx git.repo.test --what unit --mode apply --thorough` reported 94 passed, 0 failed, 0 skipped, and still exit 2. the log reads `Test Suites: 6 failed, 21 passed`; all six are under `.agent/.actors/actor.via.repo=ambient/brain/.claude/plugins/…/tests/`. `test:lint:deps` reports an absent dependency `claude-code` from `./.claude/plugins/…` in the same tree.

## .the gap, precisely

- the actor's brain config dir (with its plugin marketplace checkout) lives inside the worktree, untracked
- jest's roots and depcheck's scan both walk dot dirs, so they read plugin test files and imports that belong to no package of this repo
- a ci clone has no such dir, so ci is unaffected; every local run on an actor machine reads red with no defect in the repo
- the skill's exit 2 then hides real failures behind a red that never clears

## .the shape of the fix

- template: `testPathIgnorePatterns` gains `<rootDir>/.agent/` and `<rootDir>/.claude/`; `.depcheckrc.yml` `ignore-patterns` gains `.agent` and `.claude`
- or rhachet: keep actor brain dirs outside the worktree, or behind a path every tool already skips

## .why it is not done in this round

this repo carries the local half: `jest.unit.config.ts` `testMatch` has `!**/.agent/**`, and `.depcheckrc.yml` has `ignore-patterns: [.agent, .claude]`. both files are template-managed, so the next upgrade may drop those lines, and every other repo still reads red on an actor machine. the template fix (and its jest integration + acceptance configs) belongs upstream, for every repo at once.
