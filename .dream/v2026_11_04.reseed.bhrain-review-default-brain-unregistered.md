# 🌙 dream: a bhrain upgrade must not leave the reviewer on an unregistered brain

- kind: reseed
- owner: ehmpathy/rhachet-roles-bhrain (reviewer `review` skill, its default brain) and rhachet (`upgrade` / `init`)
- caught 2026-11-04

## .the cue that fired

on `rhx route.stone.set --stone 1.vision --as arrived`, both peer lanes (dimensional-decomposition, experience-coverage) failed before review:

```
✋ ConstraintError: brain 'openrouter/deepseek/flash' is not registered
   └─ fix: a brain registers only when its provider's package is installed and its key is unlocked
```

the judge then read the two constraint lanes as 2 blockers, so the stone cannot pass.

## .the gap, precisely

- this repo's `package.json` (uncommitted) bumps `rhachet-roles-bhrain` 0.29.10 → 0.42.4; the reviewer now defaults to `openrouter/deepseek/flash`
- `node_modules/rhachet-brains-*` holds only `anthropic` and `xai`; `rhachet-brains-openrouter` (npm 0.1.4) was never added
- `.agent/keyrack.yml` declares org `whodis` and lists no `OPENROUTER_API_KEY`; keyrack holds openrouter keys only for `ehmpathy` and `ahbode`
- so the upgrade produced a route whose every peer review is dead on arrival, and the error's own fix line (`keyrack unlock`) cannot cure it

### the second gap: the keyless brain dies when nested

with the guard moved to `--brain anthropic/claude/code/sonnet` (the one brain family that needs no keyrack key), both lanes compiled, then died: `Claude Code process exited with code 1`. the guard runs inside a Claude Code session (`CLAUDECODE=1` in env); `@anthropic-ai/claude-agent-sdk@0.1.76` `sdk.mjs` holds no `CLAUDECODE` reference, so the child inherits it. a nested-session refusal is the likeliest cause. no child stderr lands in `.log/bhrain/review/*`, so the reviewer cannot tell a nested refusal from an auth or quota fault

## .the shape of the fix

- `rhachet upgrade` / `init --roles reviewer`: when a role's default brain needs a provider package, findsert that devDep and the provider's key into `keyrack.yml`, or fail the upgrade loud
- reviewer: when the default brain is unregistered, fall back to a registered brain (or name the exact install + fill commands), never fail with a fix that cannot work
- clamp: a temp repo with only `rhachet-brains-anthropic`; assert the reviewer either runs or names the install command
- `claude/code` brain: clear `CLAUDECODE` (and kin) from the child env, and write the child's stderr to the review log so an exit 1 names its cause

## .why it is not done in this round

the defect lives in two other repos; this route can only route around it with a guard edit, which needs a human grant.
