# 🌙 dream: teesafe keeps the final newline of its stdin

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, claude.tools/teesafe) · caught 2026-11-14

## .the cue that fired
a file taken from another ref via `git show <sha>:<path> | rhx teesafe <path>` lost its final newline. each one needed a read plus an edit to match the source blob byte for byte.

## .the gap, precisely
teesafe strips every trailing newline from stdin, even with `--append`. a file that ends in `\n` cannot round-trip, so `git show | rhx teesafe` cannot reproduce a blob.

## .the shape of the fix
write stdin byte for byte; trim no byte. add a clamp test: pipe `a\n` and assert the file holds 2 bytes.

## .why it is not done in this round
the defect lives in another repo's skill. the split took the files another way.
