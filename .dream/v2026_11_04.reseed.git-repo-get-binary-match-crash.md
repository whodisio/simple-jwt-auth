# 🌙 dream: git.repo.get lines must survive a binary-file match

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic skill `git.repo.get`)
- caught 2026-11-04

## .the cue that fired

`rhx git.repo.get lines --repos 'whodisio/*' --words 'simple-jwt-auth'` crashed mid-output, exit 1:

```
├─ Binary file origin/main
│  >    0: pnpm-lock.yaml matches
...
git.repo.get.operations.sh: line 1593: printf: pnpm-lock.yaml matches: invalid number
```

## .the gap, precisely

git grep emits `Binary file <ref>:<path> matches` for a binary hit. the formatter splits it on `:` as `<path>:<line>:<text>`, takes `pnpm-lock.yaml matches` as the line number, and `printf '%d'` fails. one binary hit in one repo aborts the whole org-wide search, and the repos after it are never shown.

## .the shape of the fix

- pass `-I` (`--no-binary` / skip binary) to the git grep call, or
- detect the `Binary file … matches` line and render it as `├─ <path> (binary, skipped)`
- clamp: a temp repo with a binary file that holds the word; assert exit 0 and that later repos still render

## .why it is not done in this round

the skill ships from another repo; a fix here would be overwritten on the next `rhachet upgrade`. a per-repo `--in` search works around it for this route.
