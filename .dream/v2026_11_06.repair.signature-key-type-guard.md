# 🌙 dream: isSignatureVerified lets the key type override the alg

kind: repair · owner: simple-jwt-auth maintainers · caught 2026-11-06

## .the cue that fired

the 5.3 verification gate of the `unauthed` subpath route forbids skips. two `then.skip` cases in `src/signingAlgorithm/createVerifiableSignature.test.ts` waited on a guard that rejects a key of the wrong type. the sign-side guard landed in that pr; the verify side did not.

## .the gap, precisely

- node's verify picks the mechanism from the public key's type, and the `alg` only names the hash
- so `isSignatureVerified({ alg: 'RS256', publicKey: <ec key>, ... })` verifies an ecdsa signature made with the matched private key
- a token whose header claims `RS256` but whose signature is ecdsa passes this package's verify, if the jwks serves an ec key under that kid
- the sign side checks the key family: `createVerifiableSignature` throws `SimpleJwtAuthError` on a family mismatch (`src/signingAlgorithm/getKeyTypeOfAlg.ts`)
- neither side checks the curve: a P-256 key under `ES384` (or P-384 under `ES256`) signs and verifies, so the header's `alg` again misnames the signature

## .the shape of the fix

- in `isSignatureVerified`: `crypto.createPublicKey(publicKey).asymmetricKeyType` vs `getKeyTypeOfAlg({ alg })`; a mismatch returns `false`
- a test per family: rsa alg × ec public key, ec alg × rsa public key, each `verified: false`
- on both sides, for `ES*`: `asymmetricKeyDetails.namedCurve` must be `prime256v1` for `ES256` and `secp384r1` for `ES384`; a test per curve mismatch
- a release note: a verify that passed for a mismatched pair now fails

## .why it is not done in this round

the verify path gates every server that authenticates with this package; a new `false` there is a root behavior change a release note must announce, and the wish holds the root contract unchanged. the sign-side half shipped because its only changed outcome is a loud error for a call with no correct result (fulcrum F7); a verify-side change can lock out a live token, so the commander decides it in its own pr.
