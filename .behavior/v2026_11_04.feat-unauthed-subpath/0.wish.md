# wish: a browser can decode a jwt with no signature deps in its bundle

task: whodisio/simple-jwt-auth#20

## .the gap

every browser consumer of simple-jwt-auth (whodis-client, whodis-react, whodis-react-storage-browser) only decodes claims and redacts a signature. the package root is cjs, so each browser page ships jwk-to-pem, elliptic, asn1.js, axios, parse-domain, and a crypto polyfill. on app-storefronts-web that cost ~600kb of main chunk and ~900ms of total-blocked-time in lighthouse.

## .outcome

- `simple-jwt-auth/unauthed` resolves, in ts and at runtime, to the decode-side api: getUnauthedClaims, getUnauthedHeaderClaims, redactSignature, isJSONWebToken, SimpleJwtAuthError
- its module graph reaches none of jwk-to-pem, elliptic, asn1.js, axios, parse-domain, crypto
- the root import keeps its current contract
- a clamp: a test walks the graph of the built subpath and fails if it reaches any of those deps

pr open against main with ci green; the release waits on the commander review. the three whodis browser fixes follow it.
