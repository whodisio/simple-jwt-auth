# 1.vision — a browser decodes a jwt with no signature deps

## .the outcome world

a browser lib imports from `simple-jwt-auth/unauthed`. its bundle holds the decode ops, two base64 transformers, `buffer`, and no more. a node service imports from `simple-jwt-auth` as today and notices no change.

| | before | after |
|---|---|---|
| browser import | `simple-jwt-auth` (cjs root, every op) | `simple-jwt-auth/unauthed` |
| browser graph | jwk-to-pem, elliptic, asn1.js, axios, parse-domain, crypto polyfill | decode ops + `buffer` |
| app-storefronts-web | ~600kb main chunk tax, ~900ms tbt | tax gone (to confirm after the whodis fixes land) |
| server import | `simple-jwt-auth` | unchanged |
| regression guard | none | clamp fails ci if the subpath graph reaches a dep outside its allowlist |

aha: one import line changes, and the bundle analyzer loses six packages.

## .the contract

```ts
import {
  getUnauthedClaims,
  getUnauthedHeaderClaims,
  redactSignature,
  isJSONWebToken,
  SimpleJwtAuthError,
  type MinimalTokenClaims,       // F2
  type MinimalTokenHeaderClaims, // F2
} from 'simple-jwt-auth/unauthed';
```

the five ops are the wish's list; the target libs call two of them (`getUnauthedClaims`, `redactSignature`). the two types name the generic bounds and erase at emit.

shape:
- `src/unauthed.ts` — the entry; re-exports from the extant decode files, so root and subpath share one module per op (and one `SimpleJwtAuthError` class)
- `unauthed/package.json` — stub with `main: ../dist/unauthed.js` + `types: ../dist/unauthed.d.ts` (F1). every cjs resolver and every ts mode follows it, incl. the ts node10 that every target whodis lib compiles on (case=5)
- `package.json` — `files` gains `/unauthed`. no `exports` map (F1): a map would seal today's deep paths and drop their extension lookup
- clamp — a test over built `dist/unauthed.js` that walks the static require graph (F4). it fails on any external dep outside the allowlist `{ buffer }`, and names the six wish deps (jwk-to-pem, elliptic, asn1.js, axios, parse-domain, crypto) explicitly in its assertions
- tarball test — packs the package, unpacks it to a temp `node_modules`, and requires both entries from there; the linked contract test cannot see an omission from `files` (case=6)
- readme — names the subpath for browser consumers

## .mental model

to a friend: "the decode half of simple-jwt-auth, minus the crypto." analogy: `lodash/get` vs `lodash` — one door to a small room of the same house.

| user word | our word |
|---|---|
| "decode", "read claims" | `getUnauthedClaims` |
| "the lite import", "browser entry" | subpath `unauthed` |
| "tree shake" | not the mechanism: cjs does not shake; a separate entry does the work |

`unauthed` matches the extant `getUnauthed*` names: the claims are read, never authenticated.

## .evaluation

goals:
- subpath works in ts and at runtime — yes, for every cjs consumer and every ts mode (F1); not for node esm (C14)
- graph free of the six deps — yes; checked by hand below, guarded by the clamp
- root contract unchanged — yes; `index.ts` untouched, `main` untouched, no `exports` map, so every deep path loads as today
- clamp — yes (case=4)

pros: one-line consumer change · zero runtime behavior change · one class identity across entries · cheap guard against drift; the allowlist catches deps no one has named yet.

cons: two ways to import the same op · node esm cannot use the subpath (C14) · a future subpath needs its own stub dir and a `files` line · browser consumers who never switch stay heavy (C8; the readme is the only nudge).

pit of success:
- a verify op is absent from the subpath, so ts errors at the import, not a crypto throw at runtime (C13)
- `instanceof SimpleJwtAuthError` holds whichever entry the class came from (C3)
- the clamp names the dep and the chain, so the fix is plain (C9)

## .groundwork

### external research
- node packages (https://nodejs.org/api/packages.html): a set `exports` seals every unlisted subpath (`ERR_PACKAGE_PATH_NOT_EXPORTED`), and pattern targets are a direct string swap with no extension logic. both are why F1 ships no map
- ts modules reference (https://www.typescriptlang.org/docs/handbook/modules/reference.html): `node10` ignores `exports`; directory modules may hold a `package.json` whose `types`/`main` take precedence over `index` lookups. the stub rests on that line
- webpack package exports guide (https://webpack.js.org/guides/package-exports/): webpack 5 reads `exports`. moot for F1 (no map); kept as the source for why a map would change bundler behavior

### internal research
- decode graph, by hand: `getUnauthedClaims.ts` → `base64Url/base64UrlDecode.ts` (→ `buffer`, `castBase64UrlToBase64.ts`), `isJSONWebToken.ts`, `SimpleJwtAuthError.ts`. `getUnauthedHeaderClaims.ts` adds only an `import type`, erased at emit. `redactSignature.ts` → `isJSONWebToken.ts`, `SimpleJwtAuthError.ts`. `isExpiredToken.ts` → `getUnauthedClaims.ts`. `isRedactedSignatureToken.ts` → `redactSignature.ts`
- heavy deps enter only via root: `domains/isSameSite.ts` (parse-domain), `getPublicKey/discoverJwksUriFromAuthServerMetadata.ts` (axios, jwk-to-pem → elliptic, asn1.js), `importCrypto.ts` (lazy `require('crypto')`)
- build: `tsconfig.json` `module: node16`, cjs to `dist/`; `package.json` `main: dist/index.js`, `files: ["/dist"]`, `sideEffects: false`, no `exports`
- contract test pattern: `src/contract.acceptance.test.ts` symlinks the repo into a temp `node_modules` and `require`s it; the subpath and stub tests extend it
- emit checked: `npm run build`, then `dist/getUnauthedHeaderClaims.js` requires only `./base64Url/base64UrlDecode`, `./isJSONWebToken`, `./SimpleJwtAuthError` (the `import type` is gone); `dist/base64Url/base64UrlDecode.js` requires `buffer`
- `node_modules/jwk-to-pem/package.json` deps: `asn1.js`, `elliptic`, `safe-buffer`
- `node_modules/buffer/index.js`: 58,353 bytes raw source
- `dpdm` is a devDep (`test:lint:cycles`), a candidate for the static walk
- consumer call sites (`rhx git.repo.get lines --in whodisio/<repo> --words "from 'simple-jwt-auth"`): whodis-client `src/isTokenExpired.ts`, `src/isTokenRefreshable.ts`, `src/environment/assertTokenLooksUsableForTargetEnv.ts`; whodis-react `src/logic/claims/getAuthableTokenClaims.ts`; whodis-react-storage-browser `src/logic/storage/setTokenToStorage.ts`, `src/logic/synchronization/isTokenSynchronized.ts`. whodis-react-storage-native has no import
- consumer ts: all three libs' `tsconfig.json` extend `@tsconfig/node-lts-strictest`, whose 18.12.1 config sets `module: commonjs`, `moduleResolution: node`

## .what is awkward?

- two doors to one op invite drift in docs and examples; the readme must say "browser → `/unauthed`" plainly
- a stub dir is the older idiom; an `exports` map is the declared modern one. the map would have cost the root its deep paths, so the older idiom wins here. a later move to a map must carry `./dist/*.js` extension rules or break deep imports
- the allowlist means a legit new decode dep (say, a tiny base64 lib) needs an allowlist edit; that friction is the point
