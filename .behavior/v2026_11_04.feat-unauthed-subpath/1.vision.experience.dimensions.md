# 1.vision.experience.dimensions

## .dimensions

two spaces, walked apart: the consumer space (who imports the package) and the maintainer space (who changes it). a maintainer is no consumer value, so it sits on no consumer axis.

### consumer space

| dim | axis | positions | orthogonal because |
|---|---|---|---|
| D0 | op | `getUnauthedClaims` · `getUnauthedHeaderClaims` · `redactSignature` · `isJSONWebToken` | which op runs is chosen per call, by any consumer, on any path, under any compile mode |
| D1 | actor | `browser` (a browser app, or a whodis browser lib) · `server` (a node service) | who calls is independent of which op or token |
| D2 | import path | `root` (`simple-jwt-auth`) · `unauthed` (`simple-jwt-auth/unauthed`) · `deep` (`simple-jwt-auth/dist/*`) | each actor may import from any path |
| D3 | ts compile mode | `node10` (every target whodis lib, via `@tsconfig/node-lts-strictest`) · `node16`/`bundler` (this repo, newer consumers) · `nodenext-esm` (an esm-format file, `.mts` or a `"type": "module"` package, under nodenext) | a compile option of the consumer, not tied to actor or op |
| D4 | token | `wellformed` · `redacted` (signature `__REDACTED__`) · `malformed` (not jwt-shaped) · `unparseable` (jwt-shaped, parts not json: `a.b.c`) · `absent` (`undefined`, `''`: no cookie) | the input to every op, set by the world, not the caller |
| D6 | runtime lookup | `node-cjs` (node `require`, jest) · `bundler` (webpack, metro: cjs via a directory's `package.json` `main`) · `node-esm` (node `import`: no directory imports) | the runtime that loads the module |

### maintainer space

| dim | axis | positions | orthogonal because |
|---|---|---|---|
| D5 | maintainer change | `decode-side runtime import` (a file in the unauthed graph gains a `require`) · `auth-side runtime import` (a file outside it does) · `type-only import` (an `import type`, erased at emit, on either side) | where the import lands is the maintainer's choice of file, apart from what it imports |
| D8 | dep the import reaches | `allowlisted` (`buffer`) · `not allowlisted` (the six wish deps, or any other) | which dep is imported is apart from which file imports it; any file may import any dep |
| D7 | package form | `linked` (git root symlinked, as `contract.acceptance.test.ts` does) · `packed` (the tarball `npm pack` emits, as consumers get it) | how the package reaches its reader is set at test or publish time, apart from any source change |
| D9 | emitted graph | `js` (`dist/unauthed.js`, what a runtime or bundler loads) · `d.ts` (`dist/unauthed.d.ts`, what a consumer's tsc loads) | tsc emits both from one source; an import erased from one may stay in the other (`import type` leaves the js, and stays in the d.ts) |

disclosed correlations: D8 bears on the clamp's verdict only under `decode-side runtime import`, and D7 bears only on the tarball test, not the clamp (see collapse rules). the axes stay apart because each is a separate choice; the correlations are in their effect, not their values.

the package ships no `exports` map (F1), so "reads `exports` or not" is no axis: every cjs lookup takes the same stub door.

### root sign space (outside the wish; surfaced at verification, fulcrum F7)

| dim | axis | positions | orthogonal because |
|---|---|---|---|
| D10 | private key vs alg | `fits` (key family and curve match the alg) · `other family` (an ec key under `RS*`, an rsa key under `ES*`) · `other curve` (a P-256 key under `ES384`, or the reverse) · `other key type` (an `ed25519` or `rsa-pss` key, under any alg) | the key is the caller's, the alg is the header's; any key may meet any alg |

### root verify space (outside the wish; surfaced at verification, fulcrum F9)

| dim | axis | positions | orthogonal because |
|---|---|---|---|
| D11 | header kid vs jwks | `listed` (the jwks holds a key with that kid) · `unlisted` (it holds none) | the kid is the token's, the key set is the issuer's; an issuer rotates keys apart from any token in flight |

## .the walked product

consumer space: D0 × D1 × D2 × D3 × D4 × D6 = 4 × 2 × 3 × 3 × 5 × 3 = 1080 cells. maintainer space: D5 × D8 × D7 × D9 = 3 × 2 × 2 × 2 = 24 cells. root sign space: D10 = 4 cells. root verify space: D11 = 2 cells. most collapse.

## .correlations, stated

- **D1 × D6.** `browser` meets `bundler` only: the target apps bundle. `browser × node-cjs` cannot occur (a browser has no `require`); `browser × node-esm` (native esm, no bundler) cannot import a cjs package at all. both are impossible by nature, not walked as cells. `server` meets all three lookups
- **D4 `absent` collapses into `malformed`, per op.** `new RegExp(JWT_REGEXP).test(undefined)` coerces the value to the string `"undefined"`, which fails the shape, so `isJSONWebToken` returns `false` for absent as for malformed (C22). the three value ops guard with `isJSONWebToken`, so each throws `SimpleJwtAuthError` for absent as for malformed (C3, C19, C21). read from `src/isJSONWebToken.ts`, `src/getUnauthedClaims.ts`, `src/redactSignature.ts`
- **D4 `unparseable` does not collapse into `malformed`.** it passes the `isJSONWebToken` shape guard, so the two decode ops reach `JSON.parse` and throw the engine's raw `SyntaxError`, while `redactSignature` never parses and redacts it (C28)
- **no `system` actor.** an unattended caller (cron, probe, build step) decodes a token in node; at runtime it is the `server` actor on the same lookups. no target lib holds one

## .collapse rules

- D4 matters only once a path loads; walk D4 on `unauthed` alone (root behavior is unchanged and already tested)
- D0 matters only with D4: each op is walked across the token states; D1/D2/D3/D6 do not vary what an op does once loaded (one module file per op)
- D2 `root` and `deep` load exactly as today (no `exports`, `main` untouched), so D3 and D6 do not vary them. D1 still does: each actor × path pair gets a cell (C4, C6, C8, C24)
- D3 matters only for `unauthed` types; `node10` and `node16`/`bundler` read a directory's `package.json` `types` for a cjs import. `nodenext-esm` reads it too, so it compiles, though D6 `node-esm` then refuses the same import at runtime (C27)
- D6 `node-esm` matters only for `server` × `unauthed` (C14)
- D7 matters only for `unauthed` (a new path, so a new risk of absence from `files`); every consumer meets `packed`, every local test meets `linked`, and the gap between them is the cell to guard
- D8 matters only for `decode-side runtime import`: an auth-side or type-only import never enters the unauthed graph, so the dep it reaches cannot change the clamp's verdict (C10, C11)
- D5 × D8 × D7 collapses to D5 × D8 for the clamp (it reads built `dist/`, the same in both forms) plus C16 for the tarball
- D9 matters only for `type-only import`: a runtime import lands in both graphs, so the js walk already sees it (C9); a type-only import leaves only the d.ts, so the d.ts walk is the cell that guards it (C26)

the cells that survive collapse are verdicted in `1.vision.experience.case=_.md`.
